One Best Price Autos

  • Role: Chief Technology Officer and sole developer
  • Timeline: October 2026 – Present
  • Live site: onebestpriceautos.com
  • Repository: github.com/GabrielGimenoAlberti/one-best-price-autos

Overview

A production web platform for an independent used-car dealership. Customers browse and filter the current inventory and contact the dealer about a vehicle. Dealership staff manage inventory, photos, and customer inquiries from a private admin dashboard. I designed, built, deployed, and now operate the entire system, and I chose the architecture so that the only recurring cost is the domain name.

What I Built

Customer experience

  • Inventory browsing with filters (make, body type, fuel type, price, year, mileage), sorting, and pagination.
  • Filters are stored in the URL, so any search can be bookmarked or shared.
  • Vehicle pages with a photo gallery (arrows, swipe, and keyboard navigation), specifications, and features.
  • Inquiry forms on every vehicle page, plus a general inquiry form for when nothing in stock fits.
  • Responsive, mobile-first design with a custom glass-style interface in the dealership's brand colors.

Admin dashboard

  • Add, edit, and delete vehicles, and mark them available, pending, or sold.
  • Photo upload and removal with automatic resizing.
  • Inquiry inbox with new and handled states, plus an email alert whenever a lead arrives.
  • Handled inquiries are deleted automatically after 90 days to limit stored personal data.

Technology

Backend

Data and services

Hosting and workflow

Netlify (frontend), Render (API), Porkbun (domain and DNS), Git with a feature-branch and pull-request workflow

Engineering Highlights

Security

  • Passwords hashed with bcrypt; the hash is excluded from database queries by default.
  • JWT stored in an httpOnly cookie so scripts in the browser cannot read it.
  • Role-based access control on every admin route, verified against the database on each request.
  • Public registration can only create customer accounts; admin accounts are created by a server-side script.
  • Strict Zod validation on all request bodies and query strings, which also blocks NoSQL operator injection.
  • Rate limiting on login, registration, and the inquiry form, along with security headers and a CORS allowlist.

Performance and search visibility

  • Server-rendered pages with per-vehicle titles and descriptions.
  • Dynamic sitemap and robots.txt so new vehicles are discoverable.
  • Compound MongoDB indexes on the fields customers filter by, with paginated, stably sorted queries.
  • Images served from a CDN and lazy-loaded.

Running at $0/month beyond the domain

  • Selected hosting for each layer based on free-tier terms, including permitted commercial use.
  • Kept storage costs near zero by storing only image URLs in the database, resizing photos on upload, and deleting a vehicle's photos when the vehicle is removed.
  • Scheduled a health-check request to keep the free API instance responsive.

Process

  • Separate development and production databases and secrets, with nothing sensitive committed to the repository.
  • Changes flow from feature branches to a development branch to production through pull requests.

Challenges and Decisions

Cookies across the site and API

Login relies on a same-site cookie, which the browser drops when the frontend and API sit on unrelated hosting domains. I put both under one custom domain, with the API on a subdomain, so authentication works securely in production.

Choosing hosting under free-tier rules

One popular host's free plan prohibits commercial use, so I compared terms and chose a provider that allows it. I also accepted known tradeoffs, such as occasional cold starts on the free API tier and no automated backups on the free database tier, and planned mitigations for each.

Protecting customer data

Because the site collects names, emails, and phone numbers, I limited what is stored, set automatic expiry for handled inquiries, sent plain-text email alerts to avoid injecting customer input into HTML, and wrote privacy and terms pages.
